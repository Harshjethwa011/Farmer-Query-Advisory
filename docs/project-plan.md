# Project plan

1. Establish Vite client and Express/Mongoose server foundations.
2. Add validated data models, authentication, and protected REST endpoints.
3. Build responsive landing, farmer dashboard, profile, and navigation.
4. Connect AI query workflow and persistent, searchable history.
5. Add structured crop knowledge module and cautious information copy. **Complete:** source-attributed crop catalog, public validated list/detail API, searchable responsive directory, and matched crop context for the assistant.
6. Add authenticated bounded disease image upload, validation, and a replaceable server-side provider contract with explicit unavailable behavior. **Complete:** JPEG/PNG/WebP validation, transient uploads, rate limiting, safe provider response normalization, and tests; real model classification remains unverified and requires a compatible provider.
7. Add weather provider adapter, location search/geolocation, seven-day forecast, cautious weather notes, and provider documentation. **Complete.**
8. Add admin overview and document provider setup, API, architecture, and limitations. **Complete.**
9. Run regression, isolated MongoDB integration, browser workflow, provider-boundary, security, and submission-readiness checks. **Complete with documented blockers:** external weather egress denied in this environment; live AI and disease providers not configured. See `submission-checklist.md`.

Core provider-backed features remain explicitly unavailable until configured. Before viva demonstration, configure MongoDB and an AI provider. Weather uses Open-Meteo without a key for non-commercial use, subject to attribution and current service terms. Disease analysis needs a compatible server-side provider, its credentials, and provider-specific privacy/cost review before showing actual predictions.
